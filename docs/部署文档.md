# Rabbit 网盘 · 部署文档

> 适用版本：v1.0.0　|　两种部署方式：**Docker Compose 一键部署（推荐）** 与 **本地开发模式**

---

## 1. 环境要求

| 项目     | 要求                                                                 |
| ------ | ------------------------------------------------------------------ |
| 操作系统   | Linux（推荐 Ubuntu 22.04 / Debian 12 / CentOS Stream 9）或 Windows（开发用） |
| Docker | Docker Engine 24+ 与 Docker Compose v2                              |
| 硬件     | 最低 2 核 4GB；建议 4 核 8GB + 40GB 可用磁盘（文件存储另计）                          |
| 网络     | 服务器开放 80/443 端口；MySQL/Redis/MinIO 不对公网暴露                           |
| 浏览器    | Chrome / Edge / Firefox 最新两个大版本、Safari（backdrop-filter 已适配）        |

## 2. Docker Compose 一键部署（推荐）

### 2.1 获取代码并配置环境变量

```bash
cd rabbit-pan
cp .env.example .env
vim .env
```

**必须修改的项**（安全基线，其余可保持默认）：

```ini
MYSQL_ROOT_PASSWORD=<强密码>
DB_PASSWORD=<强密码>
MINIO_ACCESS_KEY=<自定义账号>
MINIO_SECRET_KEY=<强密码>
JWT_SECRET=<openssl rand -hex 32 的输出>     # JWT 签名密钥，>= 32 字符
SHARE_SALT=<openssl rand -hex 16 的输出>     # 12 位短链混淆盐值
ADMIN_PASSWORD=<管理员初始密码>
FRONTEND_BASE_URL=https://pan.example.com    # 对外访问域名（短链拼接/302 跳转用）
```

> ⚠️ `.env` 含全部敏感信息，务必 `chmod 600 .env` 且**禁止提交仓库**。

### 2.2 构建并启动

```bash
# 构建镜像并后台启动全部 5 个服务（首次 3-8 分钟）
docker compose up -d --build

# 观察后端启动日志：等待 Flyway 建表完成与管理员初始化提示
docker compose logs -f backend
# 出现如下日志即启动成功：
#   已初始化管理员账号: admin / <ADMIN_PASSWORD>
#   Tomcat started on port 8080
```

### 2.3 验证

| 检查项       | 方式                                                            |
| --------- | ------------------------------------------------------------- |
| 前端页面      | 浏览器打开 `http://服务器IP/`，出现液态玻璃登录页                               |
| 管理员登录     | `admin / <ADMIN_PASSWORD>` 登录，进入网盘主界面                         |
| 注册口令码     | 管理后台 → 口令码 → 生成 1-50 个，新用户注册时必填（一码一用）                         |
| 存储策略      | 系统总空间默认 30GB（全用户共享上限），新用户默认 5GB（管理后台 → 系统配置可调整）               |
| MinIO 存储桶 | `http://127.0.0.1:9001`（仅服务器本机）用 MINIO 账号登录，可见 `rabbit-pan` 桶 |
| 接口文档      | `http://服务器IP/doc.html`（Knife4j）                              |
| 容器健康      | `docker compose ps` 全部 `running`，`backend` 无重启                |

### 2.4 服务拓扑与端口策略

```
浏览器 ──80/443──> frontend (Nginx)            ← 唯一对外端口
                    ├── /           静态资源（Vue SPA）
                    ├── /api/** ──> backend:8080（Spring Boot）
                    └── /s/**   ──> backend:8080（12位短链 302）
backend ──> mysql:3306 / redis:6379 / minio:9000   （仅 docker 内网 rabbit-net）
MinIO 控制台 9001 仅绑定 127.0.0.1
```

数据库、Redis、MinIO 无公网端口；防火墙只需放行 80/443。

### 2.5 常用运维命令

```bash
docker compose ps                 # 查看状态
docker compose logs -f backend    # 后端日志（requestId 全链路）
docker compose restart backend    # 重启单个服务
docker compose down               # 停止（保留数据卷）
docker compose down -v            # ⚠️ 危险：连数据卷一起删除
docker compose up -d --build      # 代码更新后重新构建
```

## 3. HTTPS 部署（生产必须）

### 方案 A：宿主机 Nginx 终止 TLS（推荐）

1. 前端容器端口改绑本机：`docker-compose.yml` 中 frontend 的 ports 改为 `"127.0.0.1:8081:80"`，并设置 `FRONTEND_BASE_URL=https://你的域名`。
2. 宿主机安装 Nginx 与 certbot：

```bash
sudo apt install nginx certbot python3-certbot-nginx
# 使用项目内样例配置
sudo cp rabbit-pan-frontend/deploy/nginx-https.conf.example /etc/nginx/sites-available/rabbit-pan
sudo vim /etc/nginx/sites-available/rabbit-pan   # 修改 server_name 为你的域名
sudo ln -s /etc/nginx/sites-available/rabbit-pan /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
# 签发并自动配置证书（自动续期已由 certbot timer 托管）
sudo certbot --nginx -d pan.example.com
```

### 方案 B：直接修改容器 Nginx

将 `deploy/nginx-https.conf.example` 内容合并进 `deploy/nginx.conf`，挂载证书到容器并在 compose 中开放 443。

## 4. 本地开发部署

```bash
# ===== 中间件（Windows/macOS/Linux 均可用 Docker 起） =====
docker run -d --name rabbit-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 -e MYSQL_DATABASE=rabbit_pan mysql:8.0
docker run -d --name rabbit-redis -p 6379:6379 redis:7
docker run -d --name rabbit-minio -p 9000:9000 -p 9001:9001 \
  minio/minio server /data --console-address ":9001"   # 默认 minioadmin/minioadmin

# ===== 后端（JDK 17 + Maven 3.8+） =====
cd rabbit-pan-backend
mvn spring-boot:run            # 默认 dev 配置：localhost / root/123456 / minioadmin

# ===== 前端（Node 18+） =====
cd rabbit-pan-frontend
npm install
npm run dev                    # http://localhost:5173，/api 已代理到 8080
```

- 首次启动后端自动执行 Flyway 建表并创建管理员 `admin / Admin@123456`。
- 接口文档：`http://localhost:8080/doc.html`。
- 三套环境隔离：`application-dev.yml`（本机） / `application-prod.yml`（Docker，全部环境变量注入），dev/test/prod 配置**零硬编码密钥**。

## 5. 数据备份与容灾

### 5.1 MySQL 每日全量备份（crontab）

```bash
# /opt/rabbit-backup/backup-mysql.sh
#!/bin/bash
DATE=$(date +%F)
docker exec rabbit-pan-mysql sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction rabbit_pan' \
  | gzip > /opt/rabbit-backup/mysql_${DATE}.sql.gz
# 保留 14 天
find /opt/rabbit-backup -name 'mysql_*.sql.gz' -mtime +14 -delete
```

```bash
chmod +x /opt/rabbit-backup/backup-mysql.sh
crontab -e   # 添加：0 2 * * * /opt/rabbit-backup/backup-mysql.sh
```

**恢复演练**（建议每月一次）：

```bash
gunzip < mysql_2026-10-24.sql.gz | \
  docker exec -i rabbit-pan-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" rabbit_pan'
```

### 5.2 MinIO 文件数据

文件数据在 `minio-data` 数据卷中：

```bash
# 冷备：tar 打包数据卷
docker run --rm -v rabbit-pan_minio-data:/data -v /opt/rabbit-backup:/backup \
  alpine tar czf /backup/minio_$(date +%F).tar.gz -C /data .
# 恢复
docker run --rm -v rabbit-pan_minio-data:/data -v /opt/rabbit-backup:/backup \
  alpine sh -c "cd /data && tar xzf /backup/minio_日期.tar.gz"
```

生产建议将 `/opt/rabbit-backup` 同步到另一块磁盘或异地（`rsync` / 对象存储）。

### 5.3 灾难恢复预案速查

| 故障          | 处置                                                          |
| ----------- | ----------------------------------------------------------- |
| 数据库损坏       | 停 backend → 用最近备份 + 恢复演练流程重建 → 验证登录与文件列表                    |
| 磁盘空间满（核心告警） | 登录管理后台清空回收站 → 清理 `tmp/` 临时对象 → 扩容数据卷                        |
| 后端崩溃循环      | `docker compose logs --tail 200 backend` 定位；常见为密钥未配置或中间件未就绪 |
| Redis 数据丢失  | 登录态/分片任务失效可自愈（用户重新登录、前端重新上传）；短链映射会自动回源 MySQL                |

## 6. 监控与告警

### 6.1 磁盘（重中之重，80% 告警）

```bash
crontab -e
# 每天 9 点检查，超 80% 输出告警（对接邮件/钉钉/企业微信 webhook）
0 9 * * * df -P / | awk 'NR==2{gsub("%","");if($5>80) print "Rabbit网盘磁盘告警: 已用"$5"%"}' | \
  mail -s "DISK ALERT" you@example.com
```

### 6.2 服务存活

```bash
# 简易探活脚本（可对接 Uptime Kuma / 云监控）
curl -sf http://127.0.0.1/api/v1/share/000000000000/info > /dev/null || echo "backend down"
```

### 6.3 日志

- 后端：`docker compose logs backend`，每条请求日志带 `[requestId]`，支持全链路追踪；关键操作（登录/上传/删除/分享/下载）已写入 `op_log` 表，管理后台与个人中心可查。
- Nginx 访问日志：`docker logs rabbit-pan-frontend`。
- 定时任务日志关键字：`定时任务`（过期分享清理 / 回收站清理 / 存储统计）。

## 7. 常见问题（FAQ）

| 现象                                | 原因与处理                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 后端反复重启：`Connection refused mysql` | MySQL 尚未健康完成初始化；等待 `docker compose ps` 中 mysql 显示 healthy 后自动恢复                                                                      |
| 登录报 401 且前端提示过期                   | `JWT_SECRET` 与此前不一致导致旧令牌失效，重新登录即可                                                                                                    |
| 上传报“存储空间不足”                       | 用户配额用尽（默认 5GB）：管理员后台调整配额，或清理回收站释放空间；若提示“系统存储空间已满”则全系统 30GB 用尽，需扩容或清理                                                                 |
| 注册提示“口令码无效或已被使用”                  | 口令码错误/已用过/已作废：管理员后台 → 口令码 → 重新生成一个发给注册者（一码一用）                                                                                        |
| 上传报“不支持的文件类型”                     | 管理后台 → 系统配置 → 允许扩展名中添加；`exe/bat/js` 等为系统级强制拦截不可放开                                                                                    |
| 大文件合并失败                           | 分片未传全或请求超时：检查 Nginx `client_max_body_size`（≥100MB）与 `proxy_read_timeout 600s`（已内置）                                                   |
| 视频无法拖动播放                          | 确认请求未被代理层缓冲（容器 Nginx 已配置 Range 支持；自建代理需放行 206 响应）                                                                                    |
| 分享链接打开提示失效                        | 撤销/过期/超访问上限均如此；在“分享管理”中续期或重新生成                                                                                                       |
| 忘记 admin 密码                       | 用管理员SQL方式重置：`UPDATE sys_user SET password='$2a$10$...' WHERE username='admin'`（新 BCrypt 串），或删除该用户数据卷后由 ADMIN_PASSWORD 重新初始化（会丢数据，慎用） |
| 修改 .env 后不生效                      | `docker compose up -d` 重建受影响服务；backend 环境变量变更需 `docker compose up -d --force-recreate backend`                                       |
